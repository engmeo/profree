# Protocol deviations & implementation notes

- **2026-10-10.** G2/G3 implementation before any B3/holdout evaluation. `run_experiment.py` enumerates all 3 × 6 × 2 = 36 machine downtime cases for mk01; it records which outages overlap the original schedule instead of quietly filtering those cases. The original v1.0 protocol called for unimpacted cases to be reported separately; they remain in the raw file for audit, and should be excluded from *affected-case* comparisons using the recorded flag, not dropped retroactively.
- B1 wall time is measured around the greedy repair function; B2 CP-SAT wrapper reports elapsed model-construction + solve and a separate solver wall time. Future benchmarking must also include common validation overhead consistently before B1–B2 conclusions are drawn.
- The original `validate_schedule` is independent of CP-SAT but `greedy_repair` calls `validate_after` defensively. The standalone test suite includes intentional mutated schedules. This does not prove complete bug freedom.
- **Historical environment limitation (superseded on 2026-10-10)**: OR-Tools was unavailable in the initial local environment; full B2 measurements were subsequently obtained from GitHub Actions run #3, as recorded below.
- **No holdout touched** and no B3 implemented.

## G4 P1a assumptions (implementation proposal; no G4 benchmark results yet)
C0H is the original heuristic schedule; C0O will be an independently
validated CP-SAT no-event optimum when implemented. C1 minimal repair retains
original machine choices and per-machine operation ordering, respects frozen
finished/unaffected in-flight operations, and restarts failed running work
from zero. C2 is the event-time global CP-SAT solution. All four must use
matching objectives and independent validation. A no-event counterfactual
is NOT implemented in the attached P1a patch; hence do not compute or publish
G4 recovery metrics yet. A zero/negative event loss makes recovery percentage
undefined. The deterministic C1 policy is an experimental assumption, not a
claim about DENSO standard operating procedure.

## G4 unified implementation (2026-10-10; pending GitHub CI results)
- C0H = original greedy static plan, C0O = no-event global CP-SAT, C1 = deterministic delay-only minimal repair with original machines/order, C2 = global event-time CP-SAT.
- All G4 scenarios use exactly the predeclared mk01 event list (3 fractions × 6 machines × 2 durations); 14 events with `affects_plan=false` are retained and separately identifiable.
- `RUNNING_FAILED` is restarted from zero; `FINISHED` and `RUNNING_UNAFFECTED` are fixed, as in earlier G3 tests. This is a research assumption, not DENSO shop-floor policy.
- C1 is not literal "no action": it is a feasible schedule generated by a fixed delay-only rule. Its order-preservation is a particular control policy, not necessarily the best repair achievable without global optimization.
- `L_event = M(C1)-M(C0H)`, `G_response = M(C1)-M(C2)`, `G_global = M(C0H)-M(C0O)`. Recovery percentage is null when `L_event<=0`; values over 100% are not capped and must not be interpreted as a fraction of physical loss restored.
- C0O is not guaranteed OPTIMAL for larger future instances within a finite time limit; the reported solver status and bound must accompany results. Same for C2.
- CP-SAT model building/solve times are not end-to-end plant decision times; C1 and C2 time budgets differ in how they count validation. No economic ROI, DENSO equipment data, parts/QA model, holdout tests or B3 is claimed.
- G4 output must be checked via CI artifacts before any claim about observed recovery. G3 artifact is unchanged.
