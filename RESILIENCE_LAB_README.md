# FactoryPulse — Decision Backfire / Resilience Lab (P0–P3)

## What this is
A **real, browser-interactive** counterexample and stress-search lab. Its numerical outputs are generated by `resilience_lab/lab.mjs`, not hard-coded in the webpage. Run with a local HTTP server. The package deliberately **does not modify** the validated G3/G4/B3 benchmark pipeline.

**Evidence boundary:** the new P0/P1/P2 research prototype is a *reduced two-order, one-cut-line, assembly, QA, shipping scheduling model*. It does **not** invoke the repository's official CP-SAT `C1/C2/B3` implementation; in the demo those names are explicitly labelled illustrative *proxies*. It does not demonstrate broad optimality, industrial causal discovery, a DENSO deployment, ML failure prediction or measurable ROI. Do not merge its statistics with the 525-arm benchmark.

## Demo: 4 research capabilities

**P0 — Local-versus-global counterexample.** Compare A-first and B-first on the *same jobs and machines*, keeping due times and weights constant. In the default example, optimizing the local completion of A gives cut completion 14 vs 22 minutes, but factory priority-weighted tardiness is 52 vs 3 points. This is an exact exhaustive two-permutation comparison within the simplified model, not a cherry-picked screenshot. `searchParadox()` searches a fixed 3 × 3 × 3 grid (up to 27 input configurations) and returns a real counterexample or explicitly reports none.

**P1 — Explainable impact graph.** Nodes for each job's cutting, assembly, QA and delivery. Each edge has an actual precedence/resource rule and a computed time. Clicking an edge shows the evidence. It represents model-defined dependencies, not experimentally established physical causality.

**P2 — Resilience stress finder.** Exhaustively checks 3 material conditions × 3 repair delays × 4 deadline-tightening cases = 36 tests, with full samples recorded. Material state `0` denotes an *absent necessary material with no replenishment* and is blocked by definition in this reduced model. Positive-material samples permit either sequence and can exhibit a local/global KPI conflict. The finder proves only claims that follow from this finite search space; it is not an UNSAT core or general FJSP infeasibility proof.

**P3 — Interactive demo.** Sliders for processing/QA time, delivery deadlines, priorities, material and recovery time; live schedule/Gantt, KPI cards, click-to-explain dependency graph, fixed-grid search and downloadable JSON evidence. This is a usable 2D research demonstrator. A photographic 3D visualization has *not* been implemented in this package.

## How to add safely to existing profree repo

Copy **only** these new paths from `REPO_OVERLAY` into the root of `C:\Users\tuant\profree`:

```
resilience_lab/index.html
resilience_lab/style.css
resilience_lab/lab.mjs
resilience_lab/ui.mjs
resilience_lab/core.mjs
resilience_lab/worlds.mjs
tests/resilience_lab.test.mjs
RESILIENCE_LAB_README.md
```

`core.mjs` and `worlds.mjs` inside `resilience_lab/` are frozen/reference copies of the **old browser demo engine**, retained for future integration; the current counterexample solver in `lab.mjs` is self-contained. **Nothing in `factorypulse_experiment_v1/`, `src/`, existing workflows or prior artifacts needs to be replaced.**

## Run on Windows

```powershell
cd C:\Users\tuant\profree
py -m http.server 8000
```

Open `http://localhost:8000/resilience_lab/index.html`.

To test, install Node.js 18+ then:

```powershell
node --test tests/resilience_lab.test.mjs
```

An initial evidence snapshot is included in `evidence/resilience_evidence.json` in the *delivery ZIP*, and real test stdout in `evidence/test_log.txt`. The browser can download a fresh JSON for any modified scenario.

## Limitations and planned stronger validations

1. Re-implement the global/counterfactual evaluation on the **real shared CP-SAT manufacturing model** and validate on fixed schedules from G4/B3. Until then, the toy's C1/C2/B3 proxy labels must not be cited as actual CP-SAT comparisons.
2. Independently construct gold reference paths from job precedence and compare graph tracing, including machine contention.
3. Expand stress search to multi-event scenarios and distinguish solver `INFEASIBLE`, `UNKNOWN`, failed validator and modelling assumptions.
4. Add a richer 3D layer only after synchronizing its visuals with solver outputs.
